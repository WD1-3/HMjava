# 黑马点评双维学习体系：原理 + 从零手搓

> 适用对象：从 Java / Redis 项目新手开始，目标不是“看完课程”，而是最后能够独立解释、独立实现。

## 1. 学习目标不是一个维度

黑马点评以后每个模块都同时按两个维度学习：

```text
维度 A：原理理解
我知道为什么这么做吗？

维度 B：实现能力
我脱离原源码能写出来吗？
```

二者缺一不可。

只学原理容易出现：

> “我知道 Redis Session 是干什么的，但让我写登录代码就不会。”

只跟着敲代码容易出现：

> “这段代码我敲过，但为什么这样设计、换个业务还会不会，我不知道。”

因此，每个模块都采用“双轨交替”的方式推进。

---

# 维度 A：原理理解等级

## P0：听过 / 见过

表现：

- 知道名词
- 知道大概用途
- 但解释不清楚问题从哪里来

例如：

> “Redis 可以存登录状态。”

这还不算真正理解。

---

## P1：知道它解决什么问题

能够回答：

> 如果没有这个设计，会发生什么？

例如登录模块：

```text
单机 HttpSession
→ 用户登录态保存在某一台服务器
→ 多实例部署后，请求可能落到另一台服务器
→ 登录状态无法共享
→ 因此考虑把共享登录态放到 Redis
```

达到这一层，才算“知道为什么要学它”。

---

## P2：能讲清完整机制

不看源码，可以自己画出数据流。

例如：

```text
手机号
→ 验证码
→ Redis
→ 登录成功
→ token
→ Redis Hash 保存 UserDTO
→ 前端保存 token
→ 后续请求携带 token
→ 拦截器查 Redis
→ UserHolder
```

并且知道每一步的数据是什么。

---

## P3：知道设计取舍和坑

能够回答：

- 为什么这里用 Hash，不直接存整个 User？
- 为什么 token 要设置 TTL？
- 为什么需要刷新 TTL？
- 为什么 RefreshTokenInterceptor 和 LoginInterceptor 要分开？
- 为什么 UserHolder 使用 ThreadLocal？
- 如果 Redis 挂了会怎样？

这一层开始真正进入工程理解。

---

## P4：能够迁移到新问题

给一个不同项目，例如：

> “做一个论坛登录系统，多台后端服务器，需要 token 登录。”

即使没有黑马点评源码，也能自己设计：

```text
key 怎么设计
value 存什么
TTL 多久
请求如何恢复用户
登录校验放在哪里
```

达到 P4，说明这个原理真正属于自己了。

---

# 维度 B：实现 / 手搓等级

这一条线专门解决：

> 从“会认代码”到“给我空项目也能写”。

## C0：会认

看到代码能够大致说出它在做什么。

例如看到：

```java
stringRedisTemplate.opsForValue().set(...)
```

知道：

> “这是往 Redis 写一个 String，并且这里还设置了过期时间。”

此时不要求记住完整 API。

---

## C1：熟悉

同类代码看过多次后，能够：

- 认出常见 Spring 注解
- 认出 Controller → Service 调用方式
- 认出 Redis String / Hash 常用操作
- 认出 MyBatis-Plus 常见查询

这一层重点不是默写，而是建立“代码语感”。

例如看到：

```java
@PostMapping("/login")
public Result login(@RequestBody LoginFormDTO loginForm)
```

不用逐字符分析，就知道这是一个 POST 登录接口。

---

## C2：局部补全

把关键代码遮住，让自己补。

例如只给：

```java
public Result sendCode(String phone) {
    // 1. 校验手机号
    // 2. 生成验证码
    // 3. 保存到 Redis，设置 TTL
    // 4. 返回结果
}
```

自己补出主要代码。

允许：

- 查 IDE 补全
- 查 API 名字

不允许：

- 直接看原实现复制

这一层的目标是从“识别”进入“主动回忆”。

---

## C3：给骨架手搓

只给：

- 类名
- 方法签名
- 输入输出
- 业务要求

不再给步骤代码。

例如：

```text
实现 sendCode(phone)：
- 非法手机号返回失败
- 生成 6 位验证码
- 保存 Redis 2 分钟
- 返回成功
```

自己决定代码怎么组织。

达到 C3 后，才算一个功能真正“会写”。

---

## C4：只给需求，从零实现模块

不再告诉你应该有哪些方法。

例如只给需求：

> 实现一个 Redis token 登录系统：验证码登录、自动注册、token 保存登录态、请求自动恢复用户、需要登录的接口返回 401。

你需要自己决定：

```text
Controller 有哪些接口
DTO 怎么设计
Redis key 怎么设计
Service 怎么拆
拦截器怎么写
ThreadLocal 怎么封装
配置类如何注册拦截器
```

这就是“从零手搓黑马点评某个模块”。

---

## C5：迁移手搓

换掉黑马点评的业务背景，再做一次。

例如：

```text
黑马点评登录
        ↓
换成
博客系统 / 校园论坛 / 商品系统登录
```

核心能力仍然能写出来。

达到 C5，说明学到的不是“黑马点评答案”，而是 Java Web + Redis 的可迁移能力。

---

# 3. 两条线如何交替，而不是分开学

每个模块统一采用下面循环：

```text
① P1：先理解业务问题
        ↓
② C0：看一遍真实源码
        ↓
③ P2：自己画出完整机制
        ↓
④ C1：重新读代码，认识高频写法
        ↓
⑤ C2：遮住核心代码补全
        ↓
⑥ P3：追问设计取舍和边界
        ↓
⑦ C3：只给骨架自己写
        ↓
⑧ C4：只给需求，从零实现
        ↓
⑨ P4 + C5：换业务迁移一次
```

不是每一个小知识都必须做到 C5。

核心模块要求高，辅助模块要求低。

# 4. 黑马点评各模块建议目标

| 模块 | 原理目标 | 实现目标 |
| --- | --- | --- |
| 项目结构 / MVC | P2 | C2 |
| 短信登录 + Redis Session | P4 | C4 |
| 商户缓存 | P4 | C4 |
| 缓存穿透 / 击穿 / 雪崩 | P4 | C3-C4 |
| 秒杀与超卖 | P4 | C4 |
| 分布式锁 | P4 | C3-C4 |
| Lua + Redisson | P3-P4 | C3 |
| Redis Stream 异步下单 | P4 | C3-C4 |
| 点赞 / 排行 | P3 | C3 |
| Feed 流 | P4 | C3 |
| GEO | P3 | C2-C3 |
| BitMap | P3 | C3 |
| HyperLogLog | P3 | C2 |

重点是：

> 不是所有代码都要背到能默写，但项目的核心链路必须练到脱离源码可以独立实现。

# 5. 每个模块以后固定产出四份东西

## A. 原理卡

只回答：

```text
它解决什么问题？
为什么原方案不够？
核心机制是什么？
有哪些坑和取舍？
```

## B. 调用链图

例如：

```text
Controller
→ Service
→ Redis / DB
→ Interceptor
→ UserHolder
```

## C. 高频代码写法

只保留真正需要熟悉的 3~8 个写法。

例如登录模块：

```text
@PostMapping / @RequestBody
StringRedisTemplate.opsForValue()
StringRedisTemplate.opsForHash()
BeanUtil.copyProperties()
UUID.randomUUID()
ThreadLocal
HandlerInterceptor
```

## D. 手搓训练

分成：

```text
C0 认代码
C1 解释代码
C2 补代码
C3 给骨架写
C4 给需求从零写
C5 换业务再写
```

---

# 6. 判断“学会”不能再用“视频看完”

以后不使用：

```text
登录章节：已看完 ✅
```

而改成：

```text
登录模块

原理：P3 / P4
实现：C2 / C4
```

例如：

```text
原理 P3：
能解释 Redis Session、token、TTL、双拦截器、ThreadLocal。

实现 C2：
可以补出登录核心代码，但目前还不能从空白独立设计整个登录模块。
```

这能非常清楚地告诉我们下一步该练什么。

---

# 7. 第一站：登录模块

登录模块作为第一套完整训练样板，目标设置为：

```text
原理：P0 → P4
实现：C0 → C4
```

暂时不要求一开始就做到 C5。

我们会按下面顺序推进：

```text
1. 看懂 /user/code
2. 手画验证码 Redis 数据流
3. 认识 sendCode 代码写法
4. 遮住 sendCode 自己补
5. 看懂 /user/login
6. 画 token 登录链
7. 看两个拦截器
8. 理解 UserHolder + ThreadLocal
9. 给骨架重写整个登录模块
10. 最后只给需求，从零设计并手搓一遍
```

第一套模块走完之后，再把相同训练法复制到商户缓存。
